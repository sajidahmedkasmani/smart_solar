1. Project Overview

SolarEase is a Flask-based solar installation management platform. The system is designed to manage the complete workflow of a solar installation company.

The application connects customers, surveys, quotations, inventory, installations, payments, maintenance and warranty management into one system.

Main Objectives

  • Manage customer information.
  • Allow customers to register and log in.
  • Manage solar installation requirements.
  • Schedule and manage site surveys.
  • Generate solar quotations.
  • Manage solar packages.
  • Manage inventory and stock.
  • Track installations.
  • Record customer payments.
  • Manage maintenance requests.
  • Manage warranties.
  • Provide administrator functionality.
  • Provide API endpoints for system data.

Technology Stack

Python Flask Flask-SQLAlchemy SQLite Jinja2 HTML CSS JavaScript

3. Application Initialization

The main Flask application is created through the create_app() application factory.

What create_app() Does

  • Creates the Flask application.
  • Loads configuration.
  • Initializes SQLAlchemy.
  • Imports application Blueprints.
  • Registers all Blueprints.
  • Creates database tables.
  • Seeds initial data.

Application Flow

run.py ↓ create_app() ↓ Flask Application ↓ Configuration ↓ Database ↓ Blueprint Registration ↓ db.create_all() ↓ seed_data() ↓ Application Ready

4. Configuration & Database Setup

The config.py file contains the application configuration.

Database Configuration

import os

BASE_DIR = os.path.abspath(os.path.dirname(__file__))
INSTANCE_DIR = os.path.join(BASE_DIR, 'instance')

os.makedirs(INSTANCE_DIR, exist_ok=True)

class Config:

    SECRET_KEY = os.environ.get(
        'SECRET_KEY',
        'solarease-secret-key-2026'
    )

    SQLALCHEMY_DATABASE_URI = (
        os.environ.get('DATABASE_URL')
        or 'sqlite:///' +
        os.path.join(INSTANCE_DIR, 'solarease.db')
    )

    SQLALCHEMY_TRACK_MODIFICATIONS = False

Why instance/ is Important

SQLite stores the database as a file. The application uses: 

instance/solarease.db
If the instance folder does not exist, SQLite may produce:

sqlite3.OperationalError: unable to open database file

Therefore the folder should exist before the database is created, or the application can create it automatically using os.makedirs().

This module is responsible for distinguishing between different types of solar systems.

System Types

  • On-Grid: Connected to the electricity grid.
  • Off-Grid: Works independently from the grid.
  • Hybrid: Grid-connected system with battery backup.

On-Grid

An on-grid system normally operates with the electricity grid and is primarily used for reducing electricity bills.

Off-Grid

An off-grid system operates independently and requires energy storage such as batteries.

Hybrid

A hybrid system combines grid connection with battery backup, allowing the system to provide power during outages.

Comparison

System Grid Connected Battery Backup
On-Grid Yes Normally No Limited
Off-Grid No Required Yes
Hybrid Yes Yes Yes

7. Database System

SolarEase uses SQLite with SQLAlchemy as the ORM.

Why SQLAlchemy?

  • Allows Python classes to represent database tables.
  • Reduces the need to write raw SQL for normal operations.
  • Makes database queries easier to manage.
  • Works well with Flask through Flask-SQLAlchemy.

Database Creation

with app.app_context():
    db.create_all()
    seed_data()

db.create_all() creates database tables based on the SQLAlchemy models.

seed_data() inserts initial records such as solar packages, inventory items and the administrator account.

9. Understanding url_for()

Flask's url_for() generates URLs using endpoint names.

The endpoint normally follows: 

blueprint_name.function_name

Example

@inventory_bp.route('/')
def list_inventory():
    ...

The endpoint is: 

inventory.list_inventory

Therefore a template should use: 

{{ url_for('inventory.list_inventory') }}
If a template uses:

url_for('inventory.stock')

but there is no function named stock, Flask raises:

BuildError: Could not build url for endpoint 'inventory.stock'

Same Problem With Surveys

Wrong:
url_for('surveys.index')

Actual endpoint:
surveys.list_surveys

Correct:
url_for('surveys.list_surveys')

Same Problem With Quotations

Wrong:
url_for('quotations.calculator')

Available endpoint:
quotations.list_quotations

The important concept is that the endpoint name must match the Python route function name.

13. Important Errors Encountered & Their Meaning

Error 1 — TemplateNotFound

jinja2.exceptions.TemplateNotFound:
index.html

This occurs when Flask cannot find the requested template in its configured templates directory.

Error 2 — BuildError: Quotations

Could not build url for endpoint
'quotations.calculator'

The template requested an endpoint named quotations.calculator, but the routes file did not define a function called calculator.

Error 3 — BuildError: Inventory

Could not build url for endpoint
'inventory.stock'

Did you mean:
'inventory.list_inventory'?

The inventory routes contain list_inventory(), not stock().

Error 4 — BuildError: Surveys

Could not build url for endpoint
'surveys.index'

Did you mean:
'surveys.new_survey'?

The route function available for listing surveys is list_surveys(), so its endpoint is: 

surveys.list_surveys

Error 5 — SQLite Database Error

sqlite3.OperationalError:
unable to open database file

This indicates that SQLite could not open or create the database at the configured path.

In this project the database is intended to be located at: 

instance/solarease.db

The instance directory must exist or be created by the application.

16. Quotation Calculation Logic

The quotation module uses the survey's monthly electricity bill to calculate an estimated system size. 

estimated_units = survey.monthly_bill / 60.0

daily_units = estimated_units / 30.0

recommended_kw = round(
    (daily_units / 5.0) * 1.2,
    1
)

if recommended_kw < 3.0:
    recommended_kw = 3.0

panel_count = math.ceil(
    (recommended_kw * 1000) / 550
)

total_cost = recommended_kw * 220000.0

Why math.ceil()?

Solar panels cannot normally be purchased as a fraction of a panel. Therefore the calculation rounds the required number of panels upward.

17. Inventory Route Example

from flask import Blueprint, render_template

from app import db
from app.models import Inventory

inventory_bp = Blueprint(
    'inventory',
    __name__
)

@inventory_bp.route('/')
def list_inventory():

    items = Inventory.query.all()

    return render_template(
        'inventory/list.html',
        items=items
    )

This route retrieves all inventory records and passes them to the template.

The function name is list_inventory, therefore the endpoint is: 

inventory.list_inventory

22. Viva Questions & Answers

Q1. Why did you use Flask?

Flask is lightweight, flexible and suitable for building modular web applications using Python.

Q2. What is a Blueprint?

A Blueprint is a way to organize Flask routes and related functionality into separate modules.

Q3. What is SQLAlchemy?

SQLAlchemy is a Python SQL toolkit and ORM. In this project it is used through Flask-SQLAlchemy to communicate with the database.

Q4. Why SQLite?

SQLite is lightweight and does not require a separate database server, making it convenient for a small academic project and demonstration.

Q5. What does db.create_all() do?

It creates database tables defined by the SQLAlchemy models if they do not already exist.

Q6. What is seed_data()?

It inserts initial demo records into the database, such as solar packages, inventory and an administrator account.

Q7. What is Jinja2?

Jinja2 is the template engine used by Flask to generate dynamic HTML pages.

Q8. What is url_for()?

url_for() generates a URL based on a Flask endpoint name.

Q9. Why does BuildError happen?

BuildError occurs when url_for() references an endpoint that does not exist or when required route parameters are missing.

Q10. What is an ORM?

ORM means Object Relational Mapping. It allows application code to work with database records through objects and classes.
